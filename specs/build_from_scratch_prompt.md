# Build Prompt — CDM Additional Services Tracker

## What to build

A SAP BTP application for SAP Customer Delivery Managers (CDMs) to track chargeable Additional
Services (AS) requests. CDMs currently manage this across 6+ disconnected systems (Outlook,
SAP4Me, JIRA, SharePoint, APEX, AMS) using personal Excel trackers. This tool replaces that.

Build it as a CAP (Node.js) backend with an agent-native conversational UI. The CDM interacts
primarily through a chat/inbox interface backed by an AI orchestrator, not through a classic form UI.

---

## Stack

- **Backend:** SAP CAP Node.js
- **Database:** SAP HANA Cloud (HDI container)
- **Auth:** XSUAA with SAP SSO
- **AI:** SAP AI Core / Gen AI Hub (chat completions)
- **UI:** Custom HTML/JS shell (no Fiori Elements) — conversational inbox + chat panels
- **Runtime:** BTP Cloud Foundry
- **Build:** MTA (`mta.yaml`)

---

## Who uses it

- **CDM** — creates and manages AS request records, runs AI actions, tracks lifecycle
- **CDM Admin** — all CDM rights + edits reference data (R&R catalog, pricing, email templates)
- **Manager** — read-only view of all records

Define these as XSUAA role templates in `xs-security.json`.

## Data model

One central entity: `AdditionalServiceRequest`. One record per AS request.

### Fields

**Customer & service**
- `customerName` String — extracted from email by AI
- `processType` enum: `Classic` | `ATLAS` — Classic only active in v1
- `additionalServiceIds` String — R&R identifier(s), comma-separated
- `rrDescription` String — auto-filled from R&R catalog on identifier select

**System identifiers**
- `sid` String — system ID (e.g. GT3)
- `caseNo` String — SAP4Me Case number (required if no CSR)
- `csrNo` String — Chargeable SR number (required if no Case)

**Ticket numbers**
- `spcTicketNo` String
- `spcExecutionRef` String — second SPC reference
- `bcpTicketNo` String — format `NNNNNNN/YYYY`, required for O2I body
- `amsTicketNo` String — required before O2I generation
- `itsmTicketNo` String

**Pricing**
- `price` Decimal
- `currency` enum: `EUR` | `USD` | `JPY` | `GBP`
- `priceInWords` String — generated by server logic (not AI), e.g. `596.00 EUR` → `five hundred and ninety-six euros`
- `poNo` String

**Key dates**
- `creationDate` Date
- `priceCommunicatedDate` Date
- `priceValidUntil` Date — auto = priceCommunicatedDate + 90 days, editable
- `approvalReceivedDate` Date
- `customerClosureDate` Date
- `amsClosureDate` Date
- `o2iTicketCreatedDate` Date

**Invoice / O2I**
- `o2iTicketNo` String — do not validate format
- `salesOrderNo` String
- `activityPerformed` String

**Status & log**
- `status` enum (see Status States below)
- `activityLog` LargeString — free-text CDM narrative, never overwritten by system
- `cdmOwner` String — set from XSUAA user on creation

**Checklist** (all Boolean, default false)
- `priceEmailSent`
- `writtenApprovalReceived`
- `sharePointUploadDone`
- `casSDInformed`
- `amsTicketClosed`
- `o2iTicketCreated`

**Notes**
- `notes` LargeString

**Meta (auto)**
- `createdAt` DateTime
- `modifiedAt` DateTime

### Validation rule
`(caseNo IS NOT NULL) OR (csrNo IS NOT NULL)` — must be true before status can advance past `Request received`.

### Admin-editable reference entities

- `RRReference` — `{ id, description }` — R&R catalog, admin-editable
- `PricingEntry` — `{ rrId, price, currency, lastUpdated }` — pricing lookup, admin-editable
- `EmailTemplate` — `{ key, subject, body }` — email templates, admin-editable
- `AdminConfig` — `{ key, value }` — key-value settings (sharePointBaseUrl, etc.)

## Status states

Sequential. CDM can manually override. System enforces order by default.

1. `Request received`
2. `Price communicated`
3. `Approval received`
4. `In delivery`
5. `Customer closed`
6. `AMS closed`
7. `O2I ticket opened`
8. `Complete`

Log every transition: user, old status, new status, timestamp. No PII in log.

## AI layer

All AI calls go server-side only. Never expose credentials to the browser.
Use SAP AI Core / Gen AI Hub binding (`VCAP_SERVICES`). Interface must be swappable:

```javascript
// LLMClient interface
async chat(systemPrompt, userMessage) → { content: string }
```

Two implementations:
- `AnthropicDirectClient` — reads `ANTHROPIC_API_KEY` from env, for local dev only
- `GenAIHubClient` — reads Gen AI Hub credentials from VCAP_SERVICES, for BTP deployment

Selected via env flag `CDS_LLM_PROVIDER=anthropic|gen_ai_hub`.

### 5 AI actions (CAP bound actions on AdditionalServiceRequest)

**AI-1 `parseEmail(emailText)`**
Extract fields from a pasted customer email. Return JSON:
`{ customerName, serviceIdentifiers[], ticketNumbers[], poNumber }`.
Validate keys before writing to record. On low confidence show warning, do not auto-fill.

**AI-2 `matchRR(description)`**
Given a service description, return top 3 R&R matches from the catalog:
`[{ id, description, confidence: HIGH|MEDIUM|LOW }]`.
Autocomplete dropdown from catalog always available as fallback.

**AI-3 `prefillPrice(rrId)`**
NOT an LLM call. Pure JSON lookup from `PricingEntry` table.
Return `{ price, currency, lastUpdated }`.

**AI-4 `draftPriceEmail(recordId)`**
Fill email template 8.1 with record data. Return completed email text.
Do not call any send API. CDM copies to Outlook manually.

**AI-5 `generateO2IBody(recordId)`**
Generate JIRA ECSBO ticket title + body.
Only callable when `amsTicketNo` is filled AND `amsTicketClosed = true`.
Return `{ ticketTitle, ticketBody }`.

Title format: `Additional Services: [R&R IDs] [activityPerformed] [sid]`

Body format:
```
Hello ECS Global Engagement Support (ECS GES),
Please initiate the invoicing process at O2I Teams as per details below.
- Total amount with currency: [price] [currency] ([priceInWords])
- Sales order no. / Provider contract no.: [salesOrderNo]
- BCP ticket no.: [bcpTicketNo]
- PO no.: [poNo or 'Not provided']
- Activity performed: [activityPerformed]
```

## Reminder engine

Compute from record fields. Surface as pending actions in the CDM's inbox.

| Status | Condition | Message |
|---|---|---|
| Price communicated | 7 days, no approvalReceivedDate | Follow up with [customer] — price sent 7 days ago, no approval yet |
| Price communicated | 14 days, no approvalReceivedDate | URGENT: [customer] approval overdue |
| Price communicated | 85 days, no approvalReceivedDate | WARNING: price validity expires in 5 days for [customer] |
| Approval received | 3 days, sharePointUploadDone = false | Upload approval to SharePoint for [customer] |
| In delivery | 30 days, no customerClosureDate | Check delivery status for [customer] — ticket open 30+ days |
| Customer closed | 3 days, no amsClosureDate | Close AMS for [customer] |
| AMS closed | 3 days, o2iTicketCreated = false | Open O2I invoice ticket for [customer] |

## UI — agent-native shell

Do not use Fiori Elements. Build a custom HTML/JS shell with these views:

**Inbox** — default landing view
- List of pending actions (reminders, AI suggestions needing confirmation)
- PA agent chat panel — CDM types here; orchestrator routes to specialist agents
- Pending actions surface here when automation agents need CDM input

**Clients** — tree nav
- Client level → Contract/SID level → AS request records for that contract
- Each level has its own chat context

**Automations** — list of event-triggered automation agents
- Display name editable by CDM (rename via chat or inline)
- First automation: customer acceptance event → prompt CDM to create SCW/SPC ticket

**Reference data** — admin only
- R&R catalog editor (tabular)
- Pricing JSON editor (tabular)
- Email template editor

**Templates** — email + O2I templates, admin-editable

## Agent architecture

### Main Orchestrator (PA)
- Lives in Inbox
- Stateful, personalized to the CDM
- Routes messages to specialist agents silently
- CDM always sees one conversation

### Client Orchestrator
- One per customer
- Routes to correct Contract Subagent
- Can answer customer-level questions directly

### Contract Subagent
- One per contract/SID per customer
- Scoped to that contract's records
- Handles R&R, pricing, status, tickets for that contract

### Task agents (stateless)
- `emailParseAgent` — wraps AI-1
- `rrPricingAgent` — wraps AI-2 + AI-3
- `draftPriceEmailAgent` — wraps AI-4
- `generateO2IAgent` — wraps AI-5

### Handoff protocol
- CDM always sees one conversation
- Orchestrator passes to subagent: current message + injected record context + last 3–5 turns tagged to that agent
- No full history passed to subagents

## Definition of done

- `mbt build` + `cf deploy` succeeds
- App router serves shell UI at CF route
- XSUAA login works via SAP SSO
- CDM role can create a record, run parseEmail, generate O2I body
- Admin role can edit R&R catalog and pricing without code deploy
- Manager role is read-only
- At least one AI action completes via Gen AI Hub binding
- HANA HDI schema deployed with seed data
- No `ANTHROPIC_API_KEY` in CF environment
